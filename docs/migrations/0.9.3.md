# v0.9.3 — Rename init→setup, namespace all commands, parallelize post-impl checks

## What changed

### 1. Command renamed: `init` → `setup`

The `/solo-dev:init` command is now `/solo-dev:setup` to avoid conflict with Claude Code's built-in `/init` command (which creates CLAUDE.md).

### 2. All commands prefixed with `solo-dev:`

All command frontmatter names now carry the `solo-dev:` namespace prefix for clarity.

| Old | New |
|-----|-----|
| `consult` | `solo-dev:consult` |
| `decompose` | `solo-dev:decompose` |
| `evolve` | `solo-dev:evolve` |
| `go` | `solo-dev:go` |
| `handoff` | `solo-dev:handoff` |
| `init` | `solo-dev:setup` |
| `migrate` | `solo-dev:migrate` |
| `next-feature` | `solo-dev:next-feature` |
| `resume` | `solo-dev:resume` |
| `rollback` | `solo-dev:rollback` |
| `set-autonomy` | `solo-dev:set-autonomy` |
| `showcase` | `solo-dev:showcase` |
| `sprint` | `solo-dev:sprint` |
| `start-from-idea` | `solo-dev:start-from-idea` |
| `status` | `solo-dev:status` |

### 3. Post-implementation checks now run in parallel (Phase 2.5)

Gap Check, Smoke Test, and Contract Drift Check previously ran sequentially (Phases 2.5 → 2.6 → 2.7). They now dispatch simultaneously as a single Phase 2.5.

**State field change in `.solo-dev/state.json`:**

| Old `phase` values | New `phase` value |
|--------------------|-------------------|
| `GAP_CHECK` | `POST_IMPL_CHECKS` |
| `SMOKE_TEST` | `POST_IMPL_CHECKS` |
| `CONTRACT_DRIFT_CHECK` | `POST_IMPL_CHECKS` |

## Impact on existing projects

- Any project with `phase: GAP_CHECK`, `SMOKE_TEST`, or `CONTRACT_DRIFT_CHECK` in state.json was mid-check when this migration runs — safe to reset to `IMPLEMENTATION` and re-run from Phase 2.5.
- No YAML schema changes.
- No config changes.

## Migration steps

### 1. Update state.json phase value (if mid-check)

```bash
# Check current phase
cat .solo-dev/state.json | grep '"phase"'

# If phase is GAP_CHECK, SMOKE_TEST, or CONTRACT_DRIFT_CHECK:
# Reset to IMPLEMENTATION — next-feature will re-run checks from Phase 2.5
```

Edit `.solo-dev/state.json` manually:
```json
{
  "phase": "IMPLEMENTATION"
}
```

### 2. Update plugin_version

```json
{
  "plugin_version": "0.9.3"
}
```

## Verification

After migration:
1. Run `/solo-dev:status` — should show project status normally
2. Confirm `.solo-dev/state.json` contains `plugin_version: "0.9.3"`
3. If a feature was in-progress at a check phase, run `/solo-dev:resume` to continue from Phase 2.5
